# 자동화가계부 — 설계 문서

**작성일:** 2026-05-26  
**상태:** 확정  
**핵심 관점:** "가계부 앱"이 아닌 "개인 소비 데이터 자동화 엔진"

---

## 1. 프로젝트 개요

### 목표
사용자의 소비 데이터를 최대한 자동으로 수집·정규화·분류하여, 수동 입력 없이도 정확한 가계부가 완성되는 범용 SaaS.

### 플랫폼
- **앱:** Android Native + React Native CLI (Expo 제외)
- **우선 출시:** Android → iOS는 엔진 검증 후

### 기술 스택
| 역할 | 기술 |
|------|------|
| 앱 | React Native CLI |
| 인증 + DB + Storage | Supabase |
| 백엔드 로직 | Supabase Edge Functions |
| OCR (텍스트 추출) | Google Vision API 또는 Clova OCR |
| AI 후처리 + 분류 | Claude haiku API |

### MVP 기능 (출시 필수 4가지)
1. 지출 수동 입력 + 목록
2. CSV 업로드 자동 파싱
3. 영수증 OCR 스캔
4. 월별/카테고리 통계 대시보드

### MVP 출시 순서 (리스크 최소화)
1. CSV + Share Intent → 정규화 엔진 안정화
2. Notification Listener 추가
3. OCR 연동
4. UI는 엔진 검증 후 다듬기

## 3. Engine Error Handling Principles

| 상황 | 처리 |
|------|------|
| CSV 파싱 실패 | `raw_data.status = 'failed'` + `error_message` 기록 |
| OCR 실패 | 수동 입력 화면으로 fallback |
| Claude 타임아웃 | `pending_review` 저장 후 재시도 큐 등록 |

## 4. 데이터 모델

### 핵심 원칙 3가지
- 🗄️ **원본 보존:** 모든 입력은 `raw_data`에 원본 저장 → 파싱 실패 시 복구 가능
- 🔑 **중복 방지 키:** `user_id + amount + merchant + datetime(±2분)` 조합 unique
- ⚠️ **OCR 역할 분리:** Google Vision / Clova OCR = 픽셀→텍스트, Claude = 텍스트→구조화 데이터

### 테이블: `raw_data`
```sql
raw_data
├── id              uuid PK
├── user_id         uuid → auth.users (RLS 기준)
├── source          enum ('csv', 'share_intent', 'paste', 'notification', 'ocr')
├── raw_content     text       -- 원본 텍스트 그대로
├── file_path       text       -- Storage URL (CSV파일, 영수증 이미지)
├── status          enum ('pending', 'parsed', 'failed')
├── error_message   text       -- 파싱 실패 시 원인 기록
└── created_at      timestamptz
```

### 테이블: `transactions`
```sql
transactions
├── id              uuid PK
├── user_id         uuid → auth.users
├── raw_data_id     uuid → raw_data     -- 원본 추적
├── amount          numeric(12,2)       -- 음수=지출, 양수=수입
├── merchant        text                -- 상호명
├── category_id     uuid → categories
├── ai_category     text                -- AI 제안 카테고리 (원본 보존)
├── confidence      numeric(3,2)        -- 0.00 ~ 1.00
├── transaction_at  timestamptz         -- 실제 거래 시각
├── source          enum ('csv','share_intent','notification','ocr','manual')
├── status          enum ('auto_approved','pending_review','reviewed')
├── dedup_key       text UNIQUE         -- 중복 방지 키
├── memo            text
├── created_at      timestamptz
└── updated_at      timestamptz
```

### 테이블: `categories`
```sql
categories
├── id              uuid PK
├── user_id         uuid → auth.users  -- null이면 시스템 기본값
├── name            text               -- '식비', '교통', '의료'
├── icon            text               -- emoji or icon key
├── color           text               -- hex color
├── parent_id       uuid → categories  -- 대분류/소분류 지원
└── is_system       boolean            -- 기본 제공 카테고리 여부
```

### 테이블: `bank_parsers`
```sql
bank_parsers
├── id              uuid PK
├── bank_name       text        -- '국민은행', '신한은행'
├── bank_code       text UNIQUE -- 'kb', 'shinhan'
└── csv_config      jsonb       -- 컬럼 매핑 + 날짜 포맷 설정
```

```jsonc
// csv_config 예시 (국민은행)
{
  "encoding": "euc-kr",
  "date_col": "거래일시",
  "date_format": "YYYY.MM.DD HH:mm:ss",
  "amount_col": "출금액",
  "income_col": "입금액",
  "merchant_col": "적요"
}
```

### 테이블: `user_category_hints` (검수 피드백 학습)
```sql
user_category_hints
├── id           uuid PK
├── user_id      uuid → auth.users
├── merchant     text
├── category_id  uuid → categories
├── hit_count    int  -- 같은 수정이 반복될수록 신뢰도 상승
└── updated_at   timestamptz
```

### 테이블: `monthly_summary` (리포트 읽기 모델)
```sql
monthly_summary
├── id           uuid PK
├── user_id      uuid → auth.users
├── year         int
├── month        int
├── category_id  uuid → categories
├── total_amount numeric(12,2)
├── tx_count     int
└── updated_at   timestamptz

UNIQUE (user_id, year, month, category_id)
```

> 거래 INSERT/UPDATE 시 Edge Function으로 해당 월 summary만 갱신.  
> 리포트 계층은 전체 transactions를 재계산하지 않고 이 테이블만 읽음.

### MVP 이후 추가 (설계만)
```
budgets   — 카테고리별 예산 (월/주 단위)
goals     — 절약 목표
rewards   — 보상 이력
```

### RLS 정책 (전 테이블 공통)
```sql
CREATE POLICY "본인 데이터만 접근"
  ON transactions FOR ALL
  USING (user_id = auth.uid());
-- raw_data, categories, monthly_summary 동일 패턴 적용
```

## 5. 자동화 엔진 파이프라인

### 파이프라인 1: CSV 파서 (MVP 1순위)

```
사용자 CSV 업로드
  → raw_data 저장 (status: pending)
  → Edge Function: parse_csv
      ├── bank_parsers에서 은행 설정 조회
      ├── 인코딩 변환 (EUC-KR → UTF-8)
      ├── 컬럼 매핑 (날짜/금액/상호명)
      └── 행별 Transaction 객체 생성
  → dedup_key 충돌 체크
      ├── 충돌 → SKIP
      └── 통과 → AI 분류 파이프라인 진입
```

```ts
// 비즈니스 규칙: 출금액 컬럼이 있으면 지출(-), 입금액은 수입(+)
function parseKBRow(row: Record<string, string>): RawTransaction {
  const amount = row['출금액']
    ? -parseAmount(row['출금액'])
    : parseAmount(row['입금액'])
  return {
    merchant: row['적요'].trim(),
    amount,
    transaction_at: parseDate(row['거래일시'], 'YYYY.MM.DD HH:mm:ss'),
  }
}
```

### 파이프라인 2: Share Intent (MVP 1순위)

```
Android Share Intent 수신
  → raw_data 저장 (source: 'share_intent')
  → Edge Function: parse_text
      ├── 정규식 1차 파싱
      │     금액: /(\d{1,3}(,\d{3})*)\s*원/
      │     날짜: /\d{2}\/\d{2}\s\d{2}:\d{2}/
      ├── confidence 계산
      │     금액+상호명+날짜 → 0.90
      │     금액+상호명     → 0.70
      │     금액만          → 0.40
      └── confidence < 0.70 → Claude 보조 파싱 요청

MVP 지원 카드사: 국민 · 신한 · 삼성 · 현대
```

### 파이프라인 3: Notification Listener (MVP 2순위)

```
Android NotificationListenerService
  ├── 금융 앱 패키지 필터링 (com.kbcard.*, com.shinhan.*, ...)
  ├── 거래 키워드 확인: '승인', '결제', '출금', '이체'
  └── → Share Intent와 동일 파싱 파이프라인 진입

-- 주의: BIND_NOTIFICATION_LISTENER_SERVICE 권한
--       사용자 명시적 동의 필요 (민감 권한)
```

### 파이프라인 4: OCR (MVP 3순위)

```
영수증 사진 촬영 (RN Camera)
  → Supabase Storage 업로드
  → Edge Function: process_ocr
      ├── Google Vision API / Clova OCR  → 원시 텍스트 추출
      └── Claude haiku                   → JSON 구조화
            { merchant, amount, date, items[] }
```

## 6. AI 분류 파이프라인 (전 입력 공통)

```
Transaction 객체 (merchant + amount)
  → Edge Function: classify_transaction
      ├── user_category_hints 먼저 확인 (힌트 매칭 시 Claude 호출 skip)
      ├── Claude haiku 배치 호출 (최대 20건 묶음)
      └── 응답: { category, confidence, reason }
          ├── confidence >= 0.95 → auto_approved
          └── confidence  < 0.95 → pending_review
```

**Claude 프롬프트 구조:**
```
시스템: 너는 한국 가계부 분류 전문가야.
         카테고리: [식비, 교통, 의료, 쇼핑, 구독, 이체, 기타]
         반드시 JSON 배열로만 응답해.

입력: [{ id, merchant, amount }]
출력: [{ id, category, confidence, reason }]
```

## 7. 중복 방지 로직

```ts
// CSV + Notification이 같은 거래를 이중으로 가져와도 한 번만 저장
// ±2분 버킷: 초 단위를 120으로 나눠 버킷화
function generateDedupKey(tx: RawTransaction): string {
  const timeBucket = Math.floor(tx.transaction_at.getTime() / 120000)
  const raw = `${tx.user_id}|${tx.amount}|${tx.merchant}|${timeBucket}`
  return sha256(raw)
}
```

## 8. 검수 계층

**검수 UX 흐름:**
```
홈 화면 배지: "검수 대기 N건"
  → 검수 화면
      ├── 오른쪽 스와이프 → 승인 (AI 카테고리 그대로)
      ├── 왼쪽 스와이프  → 카테고리 수정 후 승인
      └── 배치 승인 버튼 (confidence >= 0.80 이상만)
```

**피드백 루프:**
```
사용자가 AI 분류 수정
  → user_category_hints에 (merchant, category) 저장
  → 다음번 동일 merchant → 힌트 우선 적용 → Claude 비용 절감
```

**주간 검수 알림:**
```
매주 일요일 오전 10시 Push 알림
"이번 주 미검수 거래 N건이 있어요 ✅"
미검수 0건이면 알림 skip
(Supabase pg_cron 또는 Edge Function cron 구현)
```

## 9. 리포트 계층

**MVP 대시보드:**
```
월별 대시보드
├── 이번 달 총 지출 / 총 수입
├── 카테고리별 지출 비중 (도넛 차트)
├── 일별 지출 추이 (바 차트)
└── 예산 대비 소진율 (카테고리별 프로그레스 바)
```

> `monthly_summary`는 대시보드 전용 읽기 모델.  
> 리포트 계층은 전체 거래를 재계산하지 않고 이 테이블만 읽는다.  
> 거래 추가/수정 시 해당 월 row만 upsert.

**MVP 이후 확장:**
```
budgets  — 카테고리별 월 예산
goals    — "이번 달 식비 30만원 이하" 목표
rewards  — 목표 달성 시 보상 뱃지
coaching — Claude 소비 패턴 분석 코멘트
```

## 10. 전체 데이터 흐름 요약

```
입력 (CSV · Share Intent · Notification · OCR)
  ↓
raw_data 원본 저장
  ↓
정규화 파서 (은행별 · 텍스트)
  ↓
dedup_key 중복 체크
  ↓
Claude 카테고리 분류
  ↓
confidence >= 0.95 → auto_approved → monthly_summary 갱신
confidence  < 0.95 → pending_review → 검수 대기열
  ↓ (검수 완료)
reviewed → monthly_summary 갱신
  ↓
리포트 계층: monthly_summary 읽어 대시보드 렌더링
```
